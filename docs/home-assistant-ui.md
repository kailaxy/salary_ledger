# Home assistant UI revision

The question composer is directly on Home, above the financial summary. It starts as a compact input row; focusing the input expands the workspace. A labeled minimize control collapses it without clearing draft text or history. Settings retains configuration and Guide; no assistant entry button or chat modal remains. The Home section is static while the dashboard summary re-renders, preserving draft text, conversation and focused input across refreshes.

The design uses the ledger's green/paper palette, serif headings, a rounded question field and an icon submit control. Two lightweight suggested questions introduce supported wording. Results distinguish monetary totals, transaction rows, category proportions, comparison columns, no matches and unsupported requests. Each successful answer shows its saved-ledger time. New cloud writes mark the snapshot stale until refresh. Device offline status is separate from snapshot age; no claim of successful network reachability is inferred from navigator.onLine.

Conversation stays in memory, bounded to ten question/answer turns, with an accessible log, a clear control and a scrollable history. Form input has an accessible label, a 44px submit target and a focus indicator. Record notes render as text. SVG icons avoid font-dependent arrow glyphs.

The expanded deterministic assistant preserves this layout. LedgerQuery.format consumes verified financial results and returns presentation data; the UI renders labels, prominent values, comparisons, breakdown percentages and explanatory rows with textContent. Long list amounts can wrap within a bounded column on narrow screens. Dates and accounting basis are visible. At most 50 rows render per answer, with truncation stated. The question reference is [assistant-questions.md](assistant-questions.md).

Deploy: replace Index.html in Apps Script and deploy a new version of the existing web app for hosted use. Install the new Actions Dev APK to update the packaged frontend. No server, schema, native source, signing or synchronization changes are required for this increment.

Current verification includes Node financial/parser regression tests and a 91-question English/Taglish corpus. Browser checks cover hosted and packaged-origin adapters, offline questions, totals/budgets/funds/loans/comparisons/averages, strict unsupported qualifiers, safe HTML-like notes, ten-turn history, draft preservation, Settings focus and no horizontal overflow at 320/393/768px. A rendered screenshot was inspected. Physical-device and live Apps Script verification are not claimed. Existing offline-write/cold-start checks remain part of the browser suite. No production dependency or model was added.

Settings opens with focus on the close button rather than the app-name input, avoiding an automatic mobile keyboard. Chromium checks verified initial compact height, expansion/minimization with preserved history, and Settings focus on the close button; native keyboard behavior should also be checked on the phone.

## Local personality controls

Settings now includes an Assistant Personality section after financial settings, with a native preset selector, labeled 0–100 step-5 range and percentage, expression band, fictional live preview, restore button and persistence status. The default is Supportive Bestie at 30%. Preferences are separate per-ledger localStorage values; no financial save/sync action is involved. Preview changes preserve control focus, and sensitive contexts always override chaos. New Home answers prepend a short deterministic reaction, rendering the canonical response and source metadata unchanged. Existing answers retain their text. Switching authenticated ledger identities clears old in-memory chat/draft and loads the new ledger's preferences, while ordinary refreshes preserve them.

The personality module is a separate data-driven layer, described in [assistant-personality.md](assistant-personality.md). Browser coverage includes keyboard slider steps/endpoints, live preview, exact canonical invariance across presets and chaos 0/50/100, offline reload, navigation/refresh persistence, identity isolation, defaults, storage denial, financial isolation and reduced-motion/mobile layouts. No LLM is integrated.
