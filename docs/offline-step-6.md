# Step 6: offline fund transfers and header spacing

The existing Add → Fund form now uses Review entry → Save on device for deposits and withdrawals. Confirmation includes direction, amount, fund, date and pay period. The available cached fund balance includes pending transfers. Pending items distinguish deposits and withdrawals; local totals update funds and unassigned amounts, never income or spending. Existing deterministic questions continue to exclude transfers from income/expense totals.

Update Code.gs, Sync.gs and Index.html, deploy a new Apps Script version, build/install a new signed APK, and refresh online once. No new sheet or migration is required when reliable sync is already prepared. The snapshot advertises fundSyncVersion=1 only with the updated sync module and a prepared journal. Older deployments cannot queue unsupported transfers.

Transfers are add-only; editing funds, loans, categories, budgets, settings and deletion remain outside offline support. The server validates fund categories and the live balance under its script lock, and records recoverable intent and terminal receipts in the existing journal. A withdrawal that exceeds the cloud balance becomes a conflict, preserving the proposal; Review cloud version lets the user explicitly discard it before reapplying an affordable amount. Script locks do not serialize simultaneous direct human Sheet edits. A cached balance is provisional until acknowledged.

Header CSS padding drops from 14px to 8px. Android explicitly lets the root handle system bars on all supported API levels, applies their insets once, then consumes them before the WebView receives them. This avoids redundant system-bar spacing while retaining cutout and keyboard clearance. Verify the visual result, keyboard and navigation on the actual phone, including rotation; browser tests cannot reproduce Android system insets.

Validation: Node tests cover capability gating, wrong category, durable fund queue, net projections and overdraw prevention. Server tests cover duplicate sends, crash recovery at each journal boundary and another device consuming funds after preparation. The browser scenario exercises the real deposit/withdrawal forms offline, confirmation direction, balance rejection and reconnect. Android build, lint and JVM tests are checked separately. Live Apps Script and physical phone behavior remain owner checks.
